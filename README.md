# lark-active-chat-digest

飞书活跃大群摘要 skill：从当前用户可见且未免打扰的飞书群中，按活跃时间找出近期活跃的大群，过滤成员数不满足条件的群，提炼每个群里最值得看的关键消息，并生成可直接发送的飞书 `interactive` 消息卡片。

它不是普通“未读消息摘要”，而是面向大群信息过载的高信号摘要工具：优先捕捉 `@所有人`、高回复/高表情互动、群主/管理员发言、关键词命中、业务/反馈类讨论等内容。

## 前置要求

### 1. 安装飞书 CLI（lark-cli）

参考官方安装文档：<https://open.feishu.cn/document/no_class/mcp-archive/feishu-cli-installation-guide.md>

常用安装与授权命令：

```bash
npm install -g @larksuite/cli
npx -y skills add https://open.feishu.cn --skill -y
lark-cli config init --new
lark-cli auth login --recommend
lark-cli auth status
```

说明：

- 需要本机已安装 Node.js / npm / npx。
- `lark-cli config init --new` 用于初始化飞书应用配置。
- `lark-cli auth login --recommend` 用于按推荐 scope 完成用户身份授权。
- 授权过程中需要打开飞书授权链接并确认。
- 读取用户自己的群聊、免打扰状态、消息和互动数据时使用 `--as user`；发送卡片通常使用 `--as bot`。

### 2. 其他依赖

除 `lark-cli` 及其运行依赖外，本 skill 本身没有额外 npm 包依赖。

仓库内脚本只使用 Node.js 内置模块：

- `scripts/build-card.mjs`：使用 `node:fs` 读取结构化摘要并生成飞书卡片 JSON。
- `evals/evals.json`：纯 JSON 测试描述文件。

所以其他人从 GitHub clone 这个 skill 后，通常只需要：

1. 把 skill 放到 Claude Code 可识别的 skills 目录中。
2. 安装并配置好 `lark-cli`。
3. 完成飞书用户授权。
4. 确认本机有 Node.js 可执行 `node scripts/build-card.mjs`。

## 可以做什么

### 1. 用飞书消息卡片输出摘要

摘要结果会生成飞书 `interactive` 消息卡片。默认先在对话里展示预览和卡片 JSON；只有用户明确要求发送，并通过 dry-run 预览后再次确认，才会真正发送到飞书。

支持：

- 发送给自己。
- 发送到指定群或会话。
- 每条摘要尽量带原消息链接。

### 2. 每个群下提炼关键消息

每个入选群会单独提炼最关键、讨论量较高、最值得关注的消息，而不是全局只取最高分几条。

重点信号包括：

- `@所有人` 消息。
- 回复数较高的消息。
- 点赞 / 表情互动较高的消息。
- 群主 / 管理员发言。
- 命中默认关键词或用户自定义关键词的消息。
- 业务类、反馈类关键词会优先。

卡片中每条结论可点击跳回飞书原消息查看上下文；带 `🚩` 的消息表示原消息包含 `@所有人`。

### 3. 支持自定义摘要范围

用户可以在每次使用时指定：

- 消息时间范围：`1天 / 3天 / 7天 / 15天`。
- 活跃群数量上限：`5 / 10 / 15 / 20`。
- 群成员数阈值：例如只看 `50人以上`、`100人以上`、`200人以上`。
- 每个群的关键信息数量：默认每群最多 10 条；可要求更少或更多，但建议避免太长。

成员数筛选规则：

- 成员数明确大于阈值：纳入候选。
- 成员数明确小于等于阈值：排除。
- 成员数无法确认：保留，但标注“人数未知”，不能声称其超过阈值。

### 4. 支持自定义忽略群白名单

用户可以要求忽略特定群，例如：

```text
以后飞书活跃大群摘要都忽略 ByteMall 可爱天使话题群和北京街舞社。
```

这些群会从常规活跃大群摘要候选中排除，并在统计中报告白名单忽略数量。

### 5. 支持自定义群优先级

用户可以要求某些群优先看、某些群降低优先级，例如：

```text
以后飞书活跃群摘要里优先看 AI 工具、产品、工程相关群。
以后 HR 闲聊群优先级降低，除非有 @所有人 或高互动。
```

这类偏好适合写入个人 memory，让 skill 后续按用户习惯排序和筛选。

### 6. 支持自定义关键词

默认关键词分为决策类、行动类、反馈类、业务类、会议类；业务类和反馈类优先级更高。

用户可以通过自然语言触发关键词配置流程，例如：

```text
我需要修改关键信息的关键词。
把反馈类增加“能不能支持”和“体验很差”。
以后业务类关键词加上“增长”“转化”。
```

关键词配置属于 skill 规则配置，通常会修改 `SKILL.md` 中的默认关键词集，而不是写入 memory。

### 7. 支持通过 memory 客制化个人偏好

如果用户只是本轮临时要求，skill 只在本轮生效；如果用户明确表达长期偏好，Agent 可以写入个人 memory。

常见触发词：

- “以后都……”
- “永远……”
- “记住……”
- “作为默认……”
- “之后每次……”

可写入 memory 的内容包括：

- 默认时间范围。
- 默认群数量上限。
- 默认成员数阈值。
- 自动忽略群白名单。
- 群优先级偏好。
- 底部专题附录偏好。
- 是否每次都追加某类横向洞察。

示例：

```text
以后默认看最近15天、最多10个群、100人以上。
永远忽略 ByteMall 可爱天使话题群、北京街舞社。
以后每次都在最后加一个“AI 工具推荐”和“AI 办公场景吐槽”的专题总结，每个专题 Top 5，并备注讨论提及次数。
```

### 8. 支持定时运行

可以让 Agent 帮你定时运行这个 skill，实现定期飞书摘要，例如：

```text
以后每周一早上 9 点跑一次 /lark-active-chat-digest，总结最近7天，最多10个群，发给我自己。
```

定时任务应遵守发送规则：真正发飞书消息属于写操作，通常需要 dry-run 和确认；如果用户希望长期自动发送，需要明确授权对应行为。

## 输出格式

### 对话内预览

会先输出简短统计和按群分组的摘要，例如：

```markdown
已筛选：最近15天、未免打扰、成员数明确>100或成员数未知、最多10个活跃群；每群最多10条关键消息。
统计：拉到群45个，白名单忽略2个，成员数明确>阈值保留8个，成员数未知保留9个，成员数<=阈值排除26个，入选候选群17个，有消息群16个，有关键消息群10个，最终摘要39条。

某群 总结
- [一句话结论](消息链接)
- 🚩 [包含 @所有人的重要通知](消息链接)
```

### 飞书卡片

使用 `interactive` 消息卡片，正文使用 `lark_md`。每个群一个标题块，每条结论是可点击链接。

`@所有人` 消息会在链接前加 `🚩`。

### 专题附录

如果用户配置了专题附录，可以在主摘要后追加横向洞察。例如：

- **专题附录：工具 / Skill / 插件 / Agent 推荐**
  - 每次 Top 5。
  - 按讨论提及次数倒序。
  - 文案使用 `【讨论提及约X次】`，避免用户误解数字含义。
- **专题附录：AI 办公高频场景 / 吐槽 / 暂无好工具**
  - 每次 Top 5。
  - 按讨论提及次数倒序。
  - 每条说明“是什么 + 出现在哪些群/语境 + 为什么值得关注/当前痛点”。

## 文件结构

```text
lark-active-chat-digest/
├── CLAUDE.md              # skill 开发规则
├── README.md              # 面向使用者的说明
├── SKILL.md               # skill 主说明、触发描述、执行流程、权限和输出约束
├── evals/
│   └── evals.json         # 行为测试提示和断言
└── scripts/
    └── build-card.mjs     # 从 digest.json 生成飞书 interactive 卡片 JSON
```


```text
总结最近7天活跃大群，最多15个群，忽略 ByteMall 可爱天使话题群，最后发给我自己。
```

```text
我需要修改关键信息的关键词。
```

```text
以后每次总结都在最后加“AI 工具推荐”和“AI 办公高频场景/吐槽”两个专题，每个专题 Top 5，并标注讨论提及次数。
```
